Proyecto Jirah - Sistema de Gestión Agrícola  4  1.3 Especificaciones de Nivel 1  
Código y Nombre  CU-01.1: Iniciar sesión  
Requisito  REQ -01.1  
Actor  Administrador, Agricultor  
Precondición  El usuario posee una cuenta registrada y activa . 
Flujo Normal  1. El usuario ingresa a la pantalla principal de login.  
2. El sistema solicita el correo electrónico y la contraseña.  
3. El usuario ingresa sus credenciales y presiona "Ingresar".  
 
4. El sistema cifra la contraseña ingresada y la compara con el hash de la 
base de datos.  
 
5. El sistema verifica que el estado de la cuenta sea "Activo".  
 
6. El sistema genera el token de sesión y redirige al usuario a la pantalla 
correspondiente a su rol (Dashboard para Admin, Pantalla de Recolección 
para Agricultor).  
 
Excepciones  E.1 Credenciales inválidas (Paso 4):  El sistema muestra el mensaje "Correo o 
contraseña incorrectos"  y limpia el campo de la contraseña. No se especifica 
cuál de los dos datos falló por seguridad.  
E.2 Cuenta inactiva (Paso 5):  El sistema bloquea el acceso y muestra el 
mensaje "Su cuenta se encuentra desactivada. Comuníquese con el 
administrador de la finca" .

=== PAGINA 5 ===
 
Proyecto Jirah - Sistema de Gestión Agrícola  5 Precondición  
El usuario se encuentra fuera de la sesión y dispone de un correo electrónico 
válido registrado.  
Flujo Normal  1. El usuario selecciona la opción "¿Olvidó su contraseña?" en la pantalla de 
login.  
2. El sistema solicita el correo electrónico asociado a la cuenta.  
3. El usuario ingresa el correo y presiona "Enviar enlace".  
4. El sistema valida la existencia del correo, genera un token temporal 
encriptado (válido por 1 hora) y envía el enlace de recuperación.  
5. El usuario accede al enlace recibido en su correo.  
 
6. El sistema muestra la pantalla de restablecimiento solicitando la nueva 
contraseña y su confirmación.  
 
7. El usuario ingresa la nueva contraseña.  
 
8. El sistema valida las políticas de complejidad y actualiza la credencial.  
 
9. El sistema muestra "Contraseña actualizada exitosamente"  y redirige al 
login.  
Excepciones  
E.1 Cuenta Inexistente:  Si el correo no existe, el sistema muestra el mensaje 
estándar: "Si el correo es válido, recibirá un enlace de recuperación"  para evitar 
filtraciones de cuentas.  
E.2 Token Caducado:  Si el usuario ingresa pasado el tiempo límite, el sistema 
indica: "El enlace de recuperación ha expirado" .

Proyecto Jirah - Sistema de Gestión Agrícola  7  2.3 Especificaciones de Nivel 1  
 
 
Código y Nombre  CU-02.2: Modificar contraseña  
Requisito  REQ -02.2  
Flujo Normal  1. El usuario selecciona "Cambiar Contraseña" dentro de su perfil.  
2. El sistema solicita la clave actual, la nueva clave y su re -confirmación.  
3. El usuario llena los campos y confirma.  
4. El sistema valida que la contraseña actual sea idéntica al hash persistido.  
5. El sistema evalúa la robustez de la nueva clave (mínimo 8 caracteres, 1 
mayúscula, 1 número).  
6. El sistema guarda los cambios de la nueva contraseña.  
Excepciones  E.1 Contraseña Actual Errónea:  El sistema cancela el proceso mostrando: "La 
contraseña actual provista es incorrecta" . 
 
Código y Nombre  CU-02.3: Modificar preferencias  
Requisito  REQ -02.3  Código y Nombre  CU-02.1: Actualizar datos  
Requisito  REQ -02.1  
Flujo Normal  1. El usuario se dirige a "Mi Perfil".  
2. El sistema muestra los datos mutables (Teléfono y Avatar/Foto). Los datos  
estructurales como cédula, rol y nombres aparecen bloqueados en modo lectura.  
3. El usuario carga una foto o edita el teléfono y presiona "Guardar".  
4. El sistema valida el formato de imagen (PNG/JPG < 2MB) y formato 
numérico  del teléfono.  
5. El sistema guarda los cambios y refresca la interfaz gráfica.  
Excepciones  
E.1 Archivo Inválido:  Si el archivo no es una imagen o supera el peso permitido, 
se arroja el error: "Formato de archivo no soportado o tamaño excedido" .

 3.3 Especificaciones de Nivel 1  
Código y Nombre  CU-03.1: Cr ear agricultor  
Requisito  REQ -03.1  
Actor  Administrador  
Precondición  El administrador ha iniciado sesión con nivel de privilegios admin  
Flujo Normal  1. El administrador ingresa al módulo de "Personal" y hace clic en "Nuevo 
Registro".  
2. El sistema muestra un formulario en blanco solicitando: Nombres, 
Apellidos, Cédula de Identidad (10 dígitos), Correo y Rol 
(Agricultor/Clasificador).  
3. El administrador ingresa la información y presiona "Guardar".  
4. El sistema valida que la cédula cumpla el algoritmo de verificación y no 
exista duplicidad de cédula o correo en la base de datos.  
5. El sistema genera automáticamente una contraseña temporal 
alfanumérica.  
6. El sistema crea el usuario y envía la credencial por correo electrónico.  
7. El sistema muestra el mensaje "Agricultor creado exitosamente" . 
 
Excepciones  
E.1 Cédula Inválida o Duplicada:  El sistema frena el almacenamiento arrojando 
el error: "Documento de identidad no válido o ya registrado en la finca" .

=== PAGINA 12 ===
 
 
Proyecto Jirah - Sistema de Gestión Agrícola  12 Flujo Normal  1. En la vista del expediente, el administrador hace clic en el botón de 
peligro "Desactivar Cuenta".  
2. El sistema despliega un modal advirtiendo: "¿Está seguro? Este 
usuario no podrá acceder al sistema, pero su historial de cosechas se 
mantendrá intacto" . 
3. El administrador confirma la acción.  
4. El sistema ejecuta un Soft-Delete  (cambia la bandera isActive  a 
falso en la base de datos).  
5. El sistema revoca inmediatamente los tokens de sesión del 
agricultor.  
6. Se muestra el mensaje: "Cuenta desactivada exitosamente" . 
Excepciones (Flujo 
Alternativo)  E.1 Auto -desactivación (Paso 3): Si el administrador intenta realizar esta 
acción sobre su propia cuenta, el sistema bloquea el flujo mostrando 
"Operación denegada. No puede desactivar su propia sesión".
